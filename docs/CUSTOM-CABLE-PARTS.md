## Authoring workflow to implement and validate

Vectorworks documents custom cable parts as symbols in the user/workgroup Cable Tools library. Refresh uses Manage Cable Parts > Update; accepting updated inventory can rebuild drawing runs. Those are separate operations requiring separate verification. The supported2026folder is `Libraries/Entertainment/Power/Cable Tools`, rather than older Defaults examples. [Vectorworks2026part management](https://app-help.vectorworks.net/2026/eng/VW2026_Guide/Cables/Managing%20cable_parts.htm).

Implementation sequence after startup resumes:

1. Open only the separate Toolkit QA document. Read actual part-symbol records from the installed `Jumper Cable.vwx` through the Resource Manager/API. Capture exact record/field names, types, units and auxiliary data. Cache attribute names are not assumed to be writable symbol-record field names.
2. Clone an appropriate official part into a uniquely named house resource, preserving required native part structure. Accept explicit length, connector names, part name/short name and cable set. Preserve source provenance and report unsupported settings. Inspect required native data before any mutation; refuse collisions rather than silently replacing in-use parts.
3. Keep physical end specifications distinct from the engine's connector-family string. Manufacturer/model/gender and catalog part number should remain reportable even when the native family combines both sexes. Do not infer TRUE1 generation, cable gauge, insulation, diameter, assembly weight or circuit rating from its name. For example, Neutrik identifies NAC3FX-W-TOP as female; that does not identify which generation the user owns. [Manufacturer reference](https://www.neutrik.com/en/product/nac3fx-w-top).
4. Save into a separate Velvet Mirror user-library file, then refresh through native Manage Cable Parts. Verify the new resource is discoverable with expected dimensions/connectors and is available for configuration. Preserve existing libraries and current-document parts settings.
5. Configure a QA native run with the custom part and inspect ordered parts, needed/stocked lengths, endpoint relationships, source assignments and worksheet output. Reopen the saved library/QA and verify persistence.
6. Test a straight male/female assembly and an adapter with different start/end families. Support any other verified native cable-part type through the same schema. Branching breakouts need actual distributor structure, not an invented second cable-part output.

One physical cable definition should not be duplicated merely for ownership. Cable-set availability and per-part inventory source are distinct data. Vectorworks suggests cable sets for company/group availability and supplies native worksheet templates for documentation. [Vectorworks power-planning workflow](https://www.vectorworks.net/en-US/newsroom/power-planning-spotlight).
