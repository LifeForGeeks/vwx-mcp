The native reference's raw UsedParts field reports Harting Cable2m despite native ordered parts TCN-5m,TCN-5ft. A live database worksheet reproduces the mismatch: ordinary record-field formulas return Harting, while `OBJECTDATA('cable section','Parts Ordered',1)` returns the correct native section sequence. Thus this mismatch also occurs on a native-tool-created object, not just our API probe. Evidence `native-cable-worksheet-comparison.json`; worksheet `VM QA Cable Native Data Comparison` remains in QA. Do not overwrite the stale raw field or infer the full required inventory from it. Ordered labels still are not stable symbol UUIDs.

A read-only EvalStr experiment returned corrupted suffixes for some record strings; it is not a reliable replacement for these worksheet/native section reads in this environment. No production tool uses that experiment. Accessibility text still reports No Selection after native selection, so a direct rendered Object Info display comparison is not established; the audit compares the stored Length record with section/geometry values.

Version 0.12.0 adds `get_cable_length_audit(object_ids, tolerance_mm=1.0)`, a read-only check for up to ten CableObjects. It compares the Object Info `Length` field, native section length, and linear path-local geometry. It also compares whole-cable and per-section part counts. The native `ValidNumStr('1mm')` conversion avoids assuming document units or using layer scale as a length conversion.

Each cable returns measurements in millimetres, individual checks, issues, and `mismatch`, `incomplete`, or `consistent_in_scope`. A null check means it was not evaluated. Length comparisons are limited to one section, no breaks, and zero vertical drop. Curves are not approximated by their chords. Agreement does not prove full initialization, world geometry, stock sufficiency, connector compatibility or electrical suitability. There is no repair operation.

The regression case is an isolated TRUE1 probe in Toolkit QA, `VM-QA-TRUE1-API-INIT`, UUID `c9fc829f-e0ae-433b-a9f2-123ba01c98d7`. An official `Jumper Powercon True1` style was imported from the installed Cable.vwx. Creating a CableObject with a NURBS path, associating the style, and setting the three public cable-type/connector parameters produced a native section. A later section-slack edit generated actual stock. However, the Object Info Length remained zero despite a 6096mm section and path; another ResetObject did not fix it. This creation recipe is an experiment, not an exposed production creator. No private endpoint fields, fake events or computed Length values were written.

A subsequent guarded experiment replaced the probe's NURBS path with an identical duplicate through documented SetCustomObjectPath, followed by ResetObject and a separate read event. Length still remained zero, while the full section snapshot, including geometry fingerprint and custom stock, matched the previous observation. Evidence: `evidence/live-qa/true1-native-path-replacement.json`. This rules out that specific replacement/reset sequence as a repair in this fixture; it does not establish the cause. A user-drawn native-tool reference is the next comparison because supported screen capture times out.

The probe is deliberately unconnected and saved as a regression fixture; body ratings are QA values. The existing Edison chain was not edited.
